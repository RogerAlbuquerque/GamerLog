# Security notes

What the application does, where it lives in the code, and what is deliberately left to deployment.

| Concern | Measure | Where |
|---|---|---|
| Password storage | `IPasswordHasher<User>` (ASP.NET Core Identity v3 format: PBKDF2, HMAC-SHA512, per-user salt, versioned so the work factor can be raised). Plain passwords are never logged or stored. | `Application/Auth` |
| Sessions | HttpOnly, `Secure`, `SameSite=Lax` cookie `gl.session`, 14-day sliding expiry. A per-user security stamp is embedded in the cookie: changing the password invalidates every other session. | `Api/Extensions/AuthExtensions.cs` |
| CSRF | Every mutating request needs an antiforgery token in `X-CSRF-TOKEN`. The token is fetched from `GET /auth/csrf` and rotated on login, register, logout and password change. A global filter enforces it, so a new controller cannot forget it. | `Api/Extensions/AntiforgeryExtensions.cs` |
| CORS | Explicit allow-list (`Cors:AllowedOrigins` / `Cors:AllowedOriginsCsv`), credentials allowed only for those origins. In the default setup the browser only talks to the Next.js origin, which proxies `/api/*`, so CORS is not exercised at all. | `Api/Extensions/CorsExtensions.cs` |
| Authorization | Fallback policy denies anonymous access; public endpoints opt in with `[AllowAnonymous]`. Ownership is checked in the service layer (private collections answer 404, not 403, to avoid confirming they exist; users can only edit their own reviews/comments; admins may delete others'). | `Api`, `Application` |
| Rate limiting | Per-client fixed windows: global 300/min, auth 10/min, write 90/min, upload 10/min (scaled by `RateLimiting:Multiplier`). Failed responses are RFC 7807 with 429. | `Api/Extensions/RateLimitingExtensions.cs` |
| Upload validation | Size cap (5 MB), real decoding with ImageSharp (the declared content type and extension are ignored), only JPEG/PNG/WebP/GIF, pixel limits (8000 px side, 40 MP), then **re-encoding to WebP with metadata stripped**. Storage keys are generated by the server and re-validated wherever a client can name one (`ObjectKeys`). | `Infrastructure/Storage/ImageSharpProcessor.cs` |
| XSS | The API returns JSON only with `Content-Security-Policy: default-src 'none'`. The web app renders all user text as escaped text (`Prose`), never `dangerouslySetInnerHTML`; spoiler text is not even present in the DOM until revealed. Unit tests cover markup in reviews and comments. | `web/src/components/ui/Prose.tsx` |
| SQL injection | EF Core parameterised queries; the few raw SQL counter updates use interpolated parameters. | `Application` |
| Account enumeration | Login failures return one generic message; registration conflicts are the only place existence is revealed (unavoidable for usernames). | `AuthService` |
| Headers | `nosniff`, `X-Frame-Options: DENY`, restrictive `Referrer-Policy`, `Permissions-Policy`, `Cache-Control: no-store` on API JSON. | both apps |
| Secrets | Nothing secret is committed. `.env` is git-ignored; `.env.example` has placeholders only; Compose refuses to start without `POSTGRES_PASSWORD`, `S3_ACCESS_KEY` and `S3_SECRET_KEY`. | repo root |
| Object storage | The bucket is private (`mc anonymous set none`); media is streamed through `GET /api/v1/media/{key}` with long-lived immutable caching. | `Api/Controllers/MediaController.cs` |
| Error handling | Unhandled exceptions become a generic RFC 7807 problem with a correlation id; details go to logs only. | `Api/Middleware` |

## Deployment checklist (not enforced by code)

- Terminate TLS in front of the web container. The session cookie is `Secure`; browsers accept it over plain `http://localhost` for development only.
- Keep the API port private. The API trusts `X-Forwarded-For` / `-Proto` because it is meant to sit behind the web proxy.
- Use long random values for `POSTGRES_PASSWORD`, `S3_*` and `SEED_ADMIN_PASSWORD`, and unset the seed admin variables after first start.
- Back up the `pgdata`, `miniodata` and `dpkeys` volumes.

## Known limitations

- No email verification or password reset flow (no mail provider is assumed).
- Rate-limit counters are in memory, so they are per API instance.
- Not independently penetration-tested; the backend was not executed against real packages in the authoring environment (see [validation.md](validation.md)).
